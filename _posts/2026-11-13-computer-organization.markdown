# 第四章 指令系统

## 4.1 指令系统概述

### 4.1.1 指令集体系结构（$ISA$）

*指令系统*就是一台计算机所有指令的集合，也称为指令集，是指令集体系结构（$ISA$）最重要的部分。

$ISA$主要包括以下内容：

- 指令格式、寻址方式、操作类型，以及各操作所需要的操作数个数、类型和寻址约束。
- 操作数的数据类型，以及数据按大端还是小端存放（详见[第一章笔记]({% link _posts/2026-11-05-computer-organization.markdown %}#co-endianness)）。
- 程序可访问的寄存器编号、数量和位数，存储空间的大小和编码方式。
- 程序员可见的控制状态，如程序计数器、条件码的定义与行为等。

### 4.1.2 指令的基本格式

一条指令通常由操作码字段和地址码字段组成：

```text
操作码字段 | 地址码字段
```

其中，操作码字段指明指令应该执行的操作及功能；地址码给出被操作信息（一般是指令或数据）的地址。

指令字长是一条指令包含的二进制位数，取决于操作码长度、地址码长度和地址码个数。

根据指令中地址码数量的不同，指令可以分为以下几种形式：

```text
零地址：OP
一地址：OP | A1
二地址：OP | A1 | A2
三地址：OP | A1 | A2 | A3
```

#### 零地址指令

仅包含操作码，没有显式地址。常见于以下两种情况：

- 不需要操作数的指令，如空操作、停机、关中断等。
- 堆栈计算机的运算指令，操作数从堆栈弹出，运算结果写回堆栈。

#### 一地址指令

指令中只有一个地址码 $A_1$。常见形式有两种：

- **单操作数指令：**按 $A_1$ 读取操作数，执行 $OP$ 操作后结果存回 $A_1$，即 $OP(A_1)\rightarrow A_1$。
- **累加器型双操作数指令：**$A_1$ 是源操作数地址，另一个操作数隐含在 $ACC$ 中，结果存入 $ACC$，即 $(ACC)OP(A_1)\rightarrow ACC$。

#### 二地址指令

指令含义为：

$$
(A_1)OP(A_2)\rightarrow A_1
$$

$A_1$ 为目的操作数地址兼结果地址，$A_2$ 为源操作数地址。

#### 三地址指令

指令含义为：

$$
(A_1)OP(A_2)\rightarrow A_3
$$

$A_1$ 和 $A_2$ 是源操作数地址，$A_3$ 是结果地址。

### 4.1.3 定长操作码的指令格式

*定长操作码指令*是在指令的高位部分分配固定位数作为操作码。例如，一个 $n$ 位操作码字段的指令系统最多能表示 $2^n$ 条指令。定长操作码有利于简化硬件设计、提高译码速度。

### 4.1.4 扩展操作码指令格式

扩展操作码属于可变操作码的一种，它使操作码的长度随地址码的减少而增加，不同地址数的指令有不同长度的操作码，从而有效缩短指令字长。

例如，指令字长 $16$ 位，前 $4$ 位是基本操作码字段 `OP`，剩下 $3$ 个 $4$ 位字段分别是地址字段 `A1`、`A2`、`A3`。若把 $16$ 个 `OP` 编码全部用于三地址指令，则最多支持 $16$ 条三地址指令。实际设计时只采用前 $15$ 个编码表示三地址指令，保留 `1111` 作为扩展标志：

- 三地址指令：`0000`～`1110`，共 $15$ 条；`1111` 留作扩展。
- 二地址指令：`1111` 后再接 $4$ 位，共 $16$ 个编码；其中 `1111 1111` 留作扩展，所以二地址指令最多 $15$ 条。
- 一地址指令：`1111 1111` 后再接 $4$ 位，共 $16$ 个编码；其中 `1111 1111 1111` 留作扩展，所以一地址指令最多 $15$ 条。
- 零地址指令：`1111 1111 1111` 后再接 $4$ 位，共 $16$ 个编码，所以零地址指令最多 $16$ 条。

操作码每扩展 $4$ 位，就少用一个 $4$ 位地址字段。

设计扩展操作码指令格式时，必须注意：

- 不允许短操作码成为长操作码的前缀。
- 各指令的操作码一定不能重复。

### 4.1.5 指令的类型

一般计算机中，指令按功能可分为以下几类：

- **数据传送指令：**`MOV`、`LOAD`、`STORE`、`PUSH`、`POP` 等。
- **算术和逻辑运算指令：**`ADD`、`SUB`、`MUL`、`DIV`、`INC`、`DEC`、`AND`、`OR`、`NOT`、`XOR` 等。
- **移位操作指令：**算术移位、逻辑移位、循环移位等。
- **程序控制指令：**`JMP`、`BRANCH`、`CALL`、`RET`、`TRAP` 等。
  - `CALL` 会保存下一条指令的地址（返回地址），以便子程序执行结束后返回主程序继续执行。
  - `JMP` 不保存返回地址。
- **输入输出指令。**
- **$CPU$ 控制指令：**停机、开中断、关中断、系统模式切换、进入特殊处理程序等。

## 4.2 寻址方式

*寻址方式*就是找到指令或操作数有效地址的方法，分为指令寻址和数据寻址两大类。

### 4.2.1 指令寻址

确定下一条即将执行的指令的地址称为*指令寻址*。有顺序寻址和跳跃寻址两种方式。

#### 顺序寻址

程序计数器（`PC`）加上当前指令的字节长度，自动形成下一条指令地址。为了便于计算，常简称为“`PC` 加 $1$ 给 `PC`”，但严格来说，只有指令长度为 $1$ 字节时才加 $1$；若指令长 $2$ 字节就加 $2$，长 $4$ 字节就加 $4$。考试常在这里挖坑。

#### 跳跃寻址

通过转移类指令实现。转移的目标地址由指令给出，转移方式分为：

- **绝对转移：**地址码直接给出目标地址。
- **相对转移：**地址码给出相对于当前 `PC` 值的偏移量，`CPU` 根据新的 `PC` 找下一条指令。

### 4.2.2 数据寻址

确定本条指令操作数地址的过程称为*数据寻址*。数据寻址方式很多，为区分不同寻址方式，指令字中设有*寻址特征*字段，其位数决定了可支持的寻址方式种类数。典型格式如下：

```text
操作码 | 寻址特征 | 形式地址 A
```

指令中的地址码字段所包含的地址称为形式地址（$A$），它不代表操作数的真实地址；真实地址需通过寻址方式由形式地址计算得出，称为有效地址（$EA$）。

#### 几种常见的数据寻址方式

- **隐含寻址：**指令不显式给出操作数地址，而将操作数地址隐含在 $ACC$ 等特定寄存器中。
- **立即寻址：**指令的形式地址字段直接存放操作数，称为*立即数*，通常以补码形式表示，即 $A=\text{操作数}$。
- **直接寻址：**形式地址 $A$ 就是真实地址 $EA$，即 $A=EA$。
- **间接寻址：**形式地址 $A$ 指向一个主存单元，该单元中存放操作数的有效地址。
- **寄存器寻址：**形式地址 $A$ 是寄存器编号，操作数存放在对应的寄存器中。
- **寄存器间接寻址：**形式地址 $A$ 是寄存器编号，对应寄存器中存放的是操作数在主存中的地址。
- **相对寻址：**将程序计数器 $PC$ 中的值与形式地址 $A$ 相加得到目标地址，即 $EA=(PC)+A$。主要用于转移类指令。这里的 $PC$ 通常指取指后的值，具体以题目约定为准。
- **基址寻址：**将基址寄存器 $BR$ 中的值与形式地址 $A$ 相加得到真实地址，即 $EA=(BR)+A$。$BR$ 可以是专用基址寄存器或指定的通用寄存器。$BR$ 的内容由操作系统指定，形式地址 $A$ 作为偏移量可由用户指定，这是它与变址寻址的差别。
- **变址寻址：**将变址寄存器 $IX$ 中的值与形式地址 $A$ 相加得到真实地址，即 $EA=(IX)+A$。$IX$ 可以是专用变址寄存器或指定的通用寄存器。$IX$ 的内容在程序执行过程中由用户动态修改，而 $A$ 作为基准地址保持不变。相对寻址、基址寻址、变址寻址都属于*偏移寻址*。
- **堆栈寻址：**堆栈是存储器或寄存器组中一块按后进先出原则管理的特定存储区，其读写单元的地址由堆栈指针 $SP$ 给出。堆栈可分为两类：
  - 硬堆栈：由高速寄存器组成，成本较高，容量较小。
  - 软堆栈：从主存中划分一段区域实现，更经济实用。
  在采用堆栈结构的计算机中，多数指令表面上表现为零地址形式，因为操作数地址由 $SP$ 隐含指定。访问堆栈时，$SP$ 会自动更新以指向新的栈顶位置。

#### 各寻址方式比较

| 寻址方式 | 有效地址 | 访存次数 |
| :---: | :---: | :---: |
| 立即寻址 | $A$ 就是操作数 | $0$ |
| 直接寻址 | $EA=A$ | $1$ |
| 一次间接寻址 | $EA=(A)$ | $2$ |
| 寄存器寻址 | $EA=(R_i)$ | $0$ |
| 寄存器间接一次寻址 | $EA=(R_i)$ | $1$ |
| 相对寻址 | $EA=(PC)+A$ | $1$ |
| 基址寻址 | $EA=(BR)+A$ | $1$ |
| 变址寻址 | $EA=(IX)+A$ | $1$ |

> 表中的访存次数一般指取操作数所需的访存次数，不含取指令本身。

## 4.3 程序的机器级代码表示

这一部分考的就是汇编指令集的部分了，历年真题主要考察 `x86` 指令集和 `MIPS` 指令集，而 `MIPS` 指令集一般在题干中会说明它们的功能，所以本节就介绍 `x86` 指令集了。

### 4.3.1 常用汇编指令介绍

#### 相关寄存器

`x86` 处理器中有 $8$ 个 $32$ 位通用寄存器。为向后兼容早期的 $16$ 位和 $8$ 位架构，`EAX`、`EBX`、`ECX`、`EDX` 的低 $16$ 位可以作为独立寄存器使用，分别记为 `AX`、`BX`、`CX`、`DX`；每个 $16$ 位寄存器又可以拆分成两个 $8$ 位寄存器。

| $16$ 位 | $32$ 位 | 说明 |
| :---: | :---: | :--- |
| `AX` | `EAX` | 累加器 |
| `BX` | `EBX` | 基地址寄存器 |
| `CX` | `ECX` | 计数寄存器 |
| `DX` | `EDX` | 数据寄存器 |
| — | `ESI` | 变址寄存器 |
| — | `EDI` | 变址寄存器 |
| — | `EBP` | 堆栈基指针 |
| — | `ESP` | 堆栈顶指针 |

`EIP` 是指令指针寄存器，相当于程序计数器 $PC$，不属于上述 $8$ 个通用寄存器。

#### 常用指令

汇编指令可分为数据传送指令、算术逻辑运算指令和控制流指令。先介绍 `Intel` 格式中表示寄存器、内存和常数的操作数标记。

##### 操作数标记

- `<reg>`：任意寄存器。后面带数字表示指定位数，如 `<reg32>` 表示 $32$ 位寄存器。
- `<mem>`：内存地址。
- `<con>`：$8$ 位、$16$ 位或 $32$ 位常数。后面带数字表示指定位数，如 `<con32>` 表示 $32$ 位常数。

##### 数据传送指令

###### `mov`

将第二个操作数（寄存器内容、内存内容或常数值）复制到第一个操作数（寄存器或内存）。语法如下：

```asm
mov <reg>, <reg>
mov <reg>, <mem>
mov <mem>, <reg>
mov <reg>, <con>
mov <mem>, <con>
```

举例：

```asm
mov eax, ebx            # 将 ebx 寄存器的值复制到 eax
mov byte ptr [var], 5   # 将常数 5 存入地址 var 处的 1 字节内存单元
```

双操作数指令的两个操作数不能同时为内存，即 `mov` 不能直接从内存复制到内存。若需要在内存之间复制，可以先把源内存内容加载到寄存器，再从该寄存器写入目标内存。

###### `push`

将操作数压入栈中，常用于函数调用和现场保护。`ESP` 是栈顶指针，入栈前先将 `ESP` 减 $4$（栈向低地址方向增长），再将操作数压入 `ESP` 所指地址。语法如下：

```asm
push <reg32>
push <mem>
push <con32>
```

栈中元素固定为 $32$ 位，所以每次入栈都要写 $4$ 字节，`ESP` 要移动 $4$ 字节。

```asm
push eax        # 将 eax 的值压入栈
push [var]      # 将地址 var 处的 4 字节内容压入栈
```

###### `pop`

与 `push` 相反，从栈中弹出数据。出栈前先读出 `ESP` 所指地址的内容，再将 `ESP` 加 $4$。语法如下：

```asm
pop <reg32>
pop <mem>
```

```asm
pop eax
pop [ebx]       # 弹出栈顶元素并存入 ebx 所指的 4 字节内存地址
```

##### 算术和逻辑运算指令

###### `add` / `sub`

`add` 将两个操作数相加，`sub` 用第一个操作数减去第二个操作数，结果都保存在第一个操作数中。语法如下：

```asm
add <reg>, <reg>        sub <reg>, <reg>
add <reg>, <mem>        sub <reg>, <mem>
add <mem>, <reg>        sub <mem>, <reg>
add <reg>, <con>        sub <reg>, <con>
add <mem>, <con>        sub <mem>, <con>
```

举例：

```asm
sub eax, 10             # eax ← eax - 10
add byte ptr [var], 10  # 将 var 处的 1 字节内容与 10 相加，结果存回该地址
```

###### `inc` / `dec`

分别对操作数执行自增 $1$ 或自减 $1$ 操作。语法如下：

```asm
inc <reg>       dec <reg>
inc <mem>       dec <mem>
```

```asm
dec eax                 # eax 的值自减 1
inc dword ptr [var]     # 将 var 处的 4 字节内容自增 1
```

###### `imul`

有符号整数乘法指令，支持两种格式：

1. 双操作数：`imul dest, src`，将 `dest` 与 `src` 相乘，结果存回 `dest`（`dest` 必须为寄存器）。
2. 三操作数：`imul dest, src, imm`，将 `src` 与立即数 `imm` 相乘，结果存入 `dest`（`dest` 必须为寄存器）。

语法如下：

```asm
imul <reg32>, <reg32>
imul <reg32>, <mem>
imul <reg32>, <reg32>, <con>
imul <reg32>, <mem>, <con>
```

第一个操作数必须是寄存器。

```asm
imul eax, [var]         # eax ← eax * [var]
imul esi, edi, 25       # esi ← edi * 25
```

无符号整数乘法由 `mul` 指令实现，只支持单操作数格式。被乘数隐含在 `eax` 中，乘积结果存放在 `edx:eax` 中。当 `edx` 不为 $0$ 时，表示结果无法用 $32$ 位无符号数表示，`CPU` 置 `CF=1`、`OF=1`。`imul` 在结果溢出时同样置 `CF=1`、`OF=1`。无符号乘法以 `CF` 判断溢出，有符号乘法则以 `OF` 为准。

###### `idiv`

有符号整数除法指令，只需指定除数。被除数是由 `edx:eax` 组成的 $64$ 位有符号数，`edx` 为高 $32$ 位，`eax` 为低 $32$ 位。执行后，商存入 `eax`，余数存入 `edx`。语法如下：

```asm
idiv <reg32>
idiv <mem>
```

```asm
idiv ebx
idiv dword ptr [var]
```

无符号整数除法指令 `div` 的格式与 `idiv` 完全一致，只是对操作数的解释不同。做有符号除法前，通常需要先把 `eax` 符号扩展到 `edx:eax`，例如使用 `cdq`。

###### `and` / `or` / `xor`

分别执行按位与、按位或、按位异或操作，结果存入第一个操作数。语法如下：

```asm
and <reg>, <reg>        or <reg>, <reg>        xor <reg>, <reg>
and <reg>, <mem>        or <reg>, <mem>        xor <reg>, <mem>
and <mem>, <reg>        or <mem>, <reg>        xor <mem>, <reg>
and <reg>, <con>        or <reg>, <con>        xor <reg>, <con>
and <mem>, <con>        or <mem>, <con>        xor <mem>, <con>
```

```asm
and eax, 0FH            # 将 eax 的高 28 位置 0，低 4 位保持不变
xor edx, edx            # 将 edx 清零
```

###### `not`

按位取反，将操作数的每一位 $0$ 变 $1$、$1$ 变 $0$。语法如下：

```asm
not <reg>
not <mem>
```

```asm
not byte ptr [var]      # 将 var 处的 1 字节内容按位取反
```

###### `neg`

取负指令，计算操作数的二进制补码，即 $-x$。语法如下：

```asm
neg <reg>
neg <mem>
```

```asm
neg eax                 # eax ← -eax
```

###### `shl` / `shr`

逻辑移位指令。`shl` 为逻辑左移，`shr` 为逻辑右移。第一个操作数是被移位数，第二个操作数是移位位数。语法如下：

```asm
shl <reg>, <con8>       shr <reg>, <con8>
shl <mem>, <con8>       shr <mem>, <con8>
shl <reg>, cl           shr <reg>, cl
shl <mem>, cl           shr <mem>, cl
```

```asm
shl eax, 1              # eax 逻辑左移 1 位
shr ebx, cl             # ebx 逻辑右移 n 位，n 为 cl 中的值
```

##### 控制流指令

`x86` 处理器通过指令指针寄存器 `EIP`（相当于程序计数器 $PC$）指示当前执行指令的地址。每条指令执行后，`EIP` 自动指向下一条指令。`EIP` 不能直接访问，但可以通过控制流指令修改。程序中常用标签（label）标记指令地址，例如：

```text
指令①
begin: 指令②
指令③
```

这里的标签 `begin` 指向第二条指令，控制流指令通过标签实现转移。

> **考点：**无条件转移指令的指令格式（$2021$）。

###### `jmp`

无条件转移到 `label` 标签所指示的地址继续执行。语法如下：

```asm
jmp <label>
```

```asm
jmp begin               # 转移到 begin 标记处执行
```

> **考点：**条件转移指令与标志位的结合（$2013$）。

###### `jcondition`

条件转移指令，根据程序状态字寄存器中的状态标志（如零标志 `ZF`、符号标志 `SF` 等）决定是否转移。常见指令如下：

- `je <label>`：相等时转移。
- `jz <label>`：结果为零时转移。
- `jne <label>`：不相等时转移。
- `jg <label>`：大于时转移。
- `jge <label>`：大于等于时转移。
- `jl <label>`：小于时转移。
- `jle <label>`：小于等于时转移。

例如：

```asm
cmp eax, ebx
jle done                # 若 eax ≤ ebx，则转移到 done；否则顺序执行下一条指令
```

###### `cmp` / `test`

`cmp` 执行减法运算但不保存结果，仅根据结果设置标志位；`test` 执行按位与运算但不保存结果，仅更新标志位（特别是 `ZF`）。语法如下：

```asm
cmp <reg>, <reg>        test <reg>, <reg>
cmp <reg>, <mem>        test <reg>, <mem>
cmp <mem>, <reg>        test <mem>, <reg>
cmp <reg>, <con>        test <reg>, <con>
```

`cmp` 和 `test` 通常与 `jcondition` 指令配合使用。

```asm
cmp dword ptr [var], 10 # 将 var 处的 4 字节内容与 10 比较
jne loop                # 若相等则顺序执行；否则转移到 loop
test eax, eax           # 测试 eax 是否为零
jz xxxx                 # 若 eax 为零（ZF=1），则转移到 xxxx
```

> **考点：**`call` 指令的功能（$2019$）。

###### `call` / `ret`

分别用于实现子程序调用与返回。语法如下：

```asm
call <label>
ret
```

`call` 指令将下一条指令的地址（返回地址）压入栈，然后转移到 `label` 处执行；`ret` 指令从栈顶弹出返回地址，并转移到该地址继续执行。`call` 和 `ret` 是函数调用机制的核心指令。

#### 汇编指令格式

统考常涉及 `Intel` 格式，所以这里只介绍 `Intel` 格式。

- `Intel` 格式不区分大小写。
- 操作数顺序是“目的, 源”。
- 用 `[]` 表示取寄存器或内存中的值。
- 内存操作数前用 `byte ptr`、`word ptr`、`dword ptr` 显式指定长度。

### 4.3.2 选择语句的机器级表示

常见的选择结构有 `if-then`、`if-then-else` 等。编译器通过设置条件码的指令和条件转移指令来实现选择结构。条件码描述最近一次算术或逻辑运算结果的属性，程序通过检测这些标志位决定是否执行条件分支。常用条件码有 `CF`、`ZF`、`SF`、`OF`。

常见算术逻辑运算指令（`add`、`sub`、`imul`、`or`、`and`、`shl`、`inc`、`dec`、`not`、`sal` 等）执行时会自动设置条件码。`cmp` 和 `test` 专门用于设置条件码：`cmp` 相当于做减法，`test` 相当于做按位与，但都不保存结果，只根据运算结果更新标志位。

前面介绍的 `jcondition` 条件转移指令，就是根据 `ZF`、`OF`、`SF` 等条件码实现转移的。

`if-else` 语句的通用形式如下：

```c
if (test_expr)          // test_expr 为条件测试表达式
{
    then_statement      // test_expr 为真时执行
}
else
{
    else_statement      // test_expr 为假时执行
}
```

在C语言中，`test_expr` 是整数表达式，值为 $0$ 表示“假”，非 $0$（包括负数）表示“真”。两个分支中只会执行其中一个。

这种通用形式可以翻译成等价的 `goto` 形式：

```c
t = test_expr;          // 暂存测试表达式的结果
if (!t)                 // 若条件为假（t = 0）
{
    goto false;         // 转到假分支
}
then_statement          // 真分支：仅当 t != 0 时执行
goto done;              // 跳过假分支
false:                  // 假分支入口
else_statement          // 假分支：仅当 t = 0 时执行
done:                   // if-else 结束点
```

例如：

```c
int get_cont(int *p1, int *p2)
{
    if (p1 > p2)
    {
        return *p2;
    }
    else
    {
        return *p1;
    }
}
```

已知 `p1` 和 `p2` 对应的实参已被压入调用函数的栈帧，存储地址分别为 $R[ebp]+8$、$R[ebp]+12$，`EBP` 指向当前栈帧底部，函数返回值存放在 `eax` 中。对应的汇编代码为：

```asm
mov eax, dword ptr [ebp+8]     # eax ← M[ebp+8]，加载 p1
mov edx, dword ptr [ebp+12]    # edx ← M[ebp+12]，加载 p2
cmp eax, edx                   # 比较 p1 与 p2，设置条件码
jbe .L1                        # 若 p1 <= p2，转到 .L1
mov eax, dword ptr [edx]       # eax ← M[edx]，取 *p2
jmp .L2                        # 跳过 else 分支
.L1:
mov eax, dword ptr [eax]       # eax ← M[eax]，取 *p1
.L2:
```

`p1` 和 `p2` 是指针型参数，在 $32$ 位机器中占 $4$ 字节（一个 `dword`）。`cmp` 的两个操作数都应来自寄存器，所以先把实参从栈中加载到寄存器。指针比较在C语言中按无符号整数处理，因此使用 `jbe`（无符号“小于等于”）进行条件转移。

### 4.3.3 循环语句的机器级表示

> **考点：**循环语句的机器级代码分析（$2014$、$2017$、$2019$、$2023$）。

常见的循环结构有 `while`、`for`、`do-while`。`x86` 指令集中没有直接对应这些高级循环结构的指令，编译器通过条件测试（如 `cmp`、`test`）和条件转移（如 `je`、`jne`、`jg`、`jle` 等）的组合来实现循环逻辑。实际上，大多数编译器会把这三种循环统一转换为类似 `do-while` 的形式。

#### do-while循环

`do-while` 是“后测试”型循环，通用形式如下：

```c
do
{
    body_statement          // 先执行循环体
}
while (test_expr);          // 再判断循环条件
```

这种结构可以直接翻译成条件转移和 `goto` 的组合：

```c
loop:                       // 循环入口
    body_statement          // 执行循环体，首次进入必然执行
    t = test_expr;          // 计算循环条件
    if (t)                  // 若条件为真（t != 0）
    {
        goto loop;          // 跳回 loop，继续下一轮
    }
```

由于循环体在条件判断之前执行，无论 `test_expr` 的初始值是什么，`body_statement` 至少执行一次。每轮结束后重新计算 `test_expr`：为真（非零）就跳回循环开头，否则顺序执行后续代码，退出循环。

#### while循环

`while` 是“前测试”型循环，通用形式如下：

```c
while (test_expr)           // 循环条件
{
    body_statement          // 条件为真时重复执行
}
```

与 `do-while` 不同，`while` 在第一次执行循环体之前就测试 `test_expr`。如果初始条件为假（`test_expr = 0`），循环体一次都不会执行。

编译器通常采用“先判断、再进入循环体”的策略，把 `while` 转换成带前置判断的 `do-while` 式结构：

```c
t = test_expr;              // 计算初始循环条件
if (!t)                     // 若初始条件为假（t = 0）
{
    goto done;              // 跳过循环体
}
do
{
    body_statement          // 执行循环体
}
while (test_expr);          // 重新测试条件
done:                       // 循环结束点
```

进一步展开为纯 `goto` 形式：

```c
t = test_expr;              // 计算初始循环条件
if (!t)                     // 若为假
{
    goto done;              // 跳过循环
}
loop:
    body_statement          // 执行循环体
    t = test_expr;          // 重新计算条件
    if (t)                  // 若仍为真
    {
        goto loop;          // 继续下一轮
    }
done:                       // 循环结束
```

这样既保证了 `while`“先判断、后执行”的语义，又复用了 `do-while` 的结构。

#### for循环

`for` 循环的通用形式如下：

```c
for (init_expr; test_expr; update_expr)
{
    body_statement
}
```

`init_expr` 是初始化表达式，用于初始化循环计数器（如 `i = 0`）；`test_expr` 是条件判断表达式，每次执行循环体前测试（如 `i < 10`）；`update_expr` 是更新表达式，每次循环体执行完后执行（如 `i++`）。

从执行逻辑上看，`for` 循环完全等价于下面的 `while` 循环：

```c
init_expr;                  // 初始化，只执行一次
while (test_expr) {         // 每次循环前判断
    body_statement          // 执行循环体
    update_expr;            // 更新循环变量
}
```

因此可以先把 `for` 转成 `while`，再按照前面的方法转成 `goto`：

```c
init_expr;                  // 执行初始化
t = test_expr;              // 测试初始条件
if (!t)                     // 若初始条件为假
{
    goto done;              // 跳过循环
}
loop:
    body_statement          // 执行循环体
    update_expr;            // 执行更新
    t = test_expr;          // 重新测试条件
    if (t)                  // 若条件仍为真
    {
        goto loop;          // 跳回循环体
    }
done:
```

例如：

```c
int nsum_for(int n)
{
    int i;
    int result = 0;
    for (i = 1; i <= n; i++)
    {
        result += i;
    }
    return result;
}
```

循环各部分对应如下：

```text
init_expr       i = 1
test_expr       i <= n
update_expr     i++
body_statement  result += i
```

将这个函数翻译成 `goto` 语句后，不难得到过程体的汇编代码：

```asm
mov ecx, dword ptr [ebp+8]     # ecx ← M[ebp+8]，加载 n
mov eax, 0                     # eax ← 0，result = 0
mov edx, 1                     # edx ← 1，i = 1
cmp edx, ecx                   # 比较 i 与 n
jg .L2                         # 若 i > n，转到 .L2
.L1:
add eax, edx                   # result += i
add edx, 1                     # i++
cmp edx, ecx                   # 再次比较 i 与 n
jle .L1                        # 若 i <= n，转到 .L1
.L2:                           # 循环结束点
```

已知实参 `n` 已被压入调用函数的栈帧，对应地址为 $R[ebp]+8$。编译器把频繁使用的局部变量优化到寄存器中：`result` 分配到 `eax`（同时也是返回值寄存器），`i` 分配到 `edx`。由于 `i` 和 `n` 均为 `int` 型，判断条件 `i <= n` 属于有符号比较，因此使用 `jle` 和 `jg` 等有符号转移指令。

### 4.3.4 过程调用的机器级表示

程序执行过程中，一个过程（函数）调用另一个过程时，需要完成参数传递、控制转移、现场保护与返回等操作。`x86` 通过 `call` 和 `ret` 指令支持这一机制。它们都属于无条件转移指令，但配合栈的使用，实现了完整的“调用—返回”语义。

假定过程P（调用者）调用过程Q（被调用者），整个调用过程大致分为以下步骤：

1. P将入口参数（实参）放到Q能访问的位置。
2. P执行 `call` 指令，将返回地址（`call` 下一条指令的地址）压入栈中，并转移到Q。
3. Q建立自己的栈帧，为局部变量分配空间，并在必要时保存某些寄存器。
4. Q执行主体代码。
5. Q将返回结果放到约定位置，释放局部变量空间，并恢复之前保存的寄存器。
6. Q执行 `ret` 指令，从栈顶弹出返回地址，并转移回P继续执行。

上述过程中，入口参数、返回地址、局部变量、返回结果以及需保护的寄存器内容，都需要在内存中找到合适的存放位置。由于寄存器数量有限，且调用双方共享寄存器资源，若不加保护直接覆盖，就会导致程序出错。因此，调用约定和栈的配合至关重要。

规定：

- `EAX`、`ECX`、`EDX` 是调用者保存寄存器。若P希望在调用后仍使用这些寄存器的值，则P必须在调用前自行保存（如压栈），并在返回后恢复。
- `EBX`、`ESI`、`EDI` 是被调用者保存寄存器。若Q需要使用这些寄存器，则Q必须在使用前将其保存到栈中，并在返回前恢复。

每个过程执行时，都会在运行时栈中分配一块专属区域，称为栈帧。整个运行时栈由多个连续的栈帧组成。`EBP`（基址指针）指向当前栈帧的基址（保存旧 `EBP` 的位置），`ESP`（栈指针）始终指向当前栈顶。栈从高地址向低地址增长；过程执行时，`ESP` 会随数据入栈/出栈动态变化，而 `EBP` 在当前过程执行期间保持不变，便于通过固定偏移访问参数和局部变量。

例如：

```c
int add(int x, int y)
{
    return x + y;
}

int caller()
{
    int temp1 = 125;
    int temp2 = 80;
    int sum = add(temp1, temp2);
    return sum;
}
```

经 `GCC` 编译后，`caller` 对应的汇编代码如下：

```asm
caller:
    push ebp                        # 保存调用者 P 的 EBP
    mov ebp, esp                    # 建立新栈帧：EBP ← 当前栈顶
    sub esp, 24                     # 为局部变量和参数区分配 24 字节
    mov dword ptr [ebp-12], 125     # temp1 = 125
    mov dword ptr [ebp-8], 80       # temp2 = 80
    mov eax, dword ptr [ebp-8]      # 加载 temp2
    mov dword ptr [esp+4], eax      # 将 temp2 放入参数区高地址
    mov eax, dword ptr [ebp-12]     # 加载 temp1
    mov dword ptr [esp], eax        # 将 temp1 放入参数区低地址
    call add                        # 调用 add，返回值在 eax
    mov dword ptr [ebp-4], eax      # sum = 返回值
    mov eax, dword ptr [ebp-4]      # 将 sum 作为返回值
    leave                           # 等价于 mov esp, ebp; pop ebp
    ret                             # 弹出返回地址并跳回
```

假设 `caller` 被过程P调用。执行完 `sub esp, 24` 后，`caller` 的栈帧已经建立，`ESP` 指向新栈顶。`GCC` 为 `caller` 分配了 $24$ 字节空间。栈帧中从高地址到低地址大致如下：

```text
高地址
[EBP]        调用者 P 的旧 EBP
[EBP-4]      sum
[EBP-8]      temp2 = 80
[EBP-12]     temp1 = 125
[EBP-16]     对齐填充（未使用）
[EBP-20]     参数 temp2 = 80
[EBP-24]     参数 temp1 = 125
[EBP-28]     call 压入的返回地址
低地址
```

- `caller` 只使用了 `EAX`（调用者保存寄存器），没有使用任何被调用者保存寄存器。因此，除了用 `push ebp` 保存P的旧 `EBP` 外，无须保存其他寄存器。
- `caller` 的三个局部变量 `temp1`、`temp2`、`sum` 都分配在栈帧中，占 $12$ 字节。
- 在调用 `add` 之前，`caller` 依次把入口参数 `temp2` 和 `temp1` 的值（$80$ 和 $125$）保存到栈中，左参数位于较低地址，右参数位于较高地址，占 $8$ 字节。
- 执行 `call` 时再把返回地址压入栈中，占 $4$ 字节。
- 包括最初压入的旧 `EBP`（$4$ 字节）在内，`caller` 栈帧实际使用 $4+12+8+4=28$ 字节。`GCC` 为保证数据严格对齐，要求栈帧大小为 $16$ 字节的倍数，最终分配 $32$ 字节，因此有 $4$ 字节作为对齐填充。

`call` 执行后，`add` 的返回值保存在 `EAX` 中。因此，`call` 后面的两条指令分别完成：

- `mov dword ptr [ebp-4], eax`：把 `add` 的结果存入变量 `sum`，地址为 $R[ebp]-4$。
- `mov eax, dword ptr [ebp-4]`：把 `sum` 的值加载到 `EAX`，作为 `caller` 的返回值。

在执行 `ret` 之前，必须释放当前栈帧并恢复调用者P的基址指针。`leave` 指令正是用于完成这一任务，其功能等价于：

```asm
mov esp, ebp                    # ESP 指向保存旧 EBP 的位置
pop ebp                         # 弹出旧 EBP，恢复 P 的基址指针
```

执行完这两条指令后，`EBP` 已恢复为P中的原始值，`ESP` 指向栈顶的返回地址。此时 `ret` 从 `ESP` 所指位置取出返回地址，并转移回P继续执行。当然，也可以不使用 `leave`，而是通过显式的 `pop` 操作配合对 `ESP` 的调整来回收栈帧。

`add` 过程经 `GCC` 编译并链接后，对应的机器代码如下：

```text
8048469: 55              push ebp
804846a: 89 e5           mov ebp, esp
804846c: 8b 45 0c        mov eax, dword ptr [ebp+12]
804846f: 8b 55 08        mov edx, dword ptr [ebp+8]
8048472: 8d 04 02        lea eax, [edx+eax]
8048475: 5d              pop ebp
8048476: c3              ret
```

通常，一个过程的机器级代码可分为三个部分：准备阶段、过程体和结束阶段。

- **准备阶段（第1、2行）：**`push ebp` 将 `caller` 的 `EBP` 值保存到栈中，随后 `mov ebp, esp` 使 `EBP` 指向当前栈帧的基址。`EBP` 指向 `add` 栈帧底部。`add` 的入口参数 `x` 和 `y` 分别在地址 $R[ebp]+8$、$R[ebp]+12$ 的存储单元中。
- **过程体（第3、4、5行）：**第3行将 `y`（`[ebp+12]`）加载到 `EAX`，第4行将 `x`（`[ebp+8]`）加载到 `EDX`。第5行用 `lea` 指令计算 `edx + eax`，并将结果存回 `EAX`，作为函数返回值。这里看起来没有加法指令，实际上 `lea` 执行的是加法运算 $R[edx]+R[eax]=x+y$。
- **结束阶段（第6、7行）：**`pop ebp` 恢复 `caller` 的 `EBP` 值，使栈帧指针回到调用前的状态；随后 `ret` 从栈顶弹出返回地址，并转移回调用点。此时栈顶正是 `call` 执行时压入的返回地址，对应 `caller` 中紧接在 `call add` 之后的那条指令。

由于 `add` 过程不包含局部变量、未使用任何被调用者保存寄存器，且不再调用其他过程，因此其栈帧结构非常简洁：只需保存 `EBP` 以维持调用链的完整性，无须额外空间用于寄存器保存、局部变量或嵌套调用。

## 4.4 $CISC$和$RISC$的基本概念

随着计算机的发展，指令系统也朝着两个截然相反的方向发展：一是通过增强原有指令功能、引入更复杂的指令，称为*复杂指令系统计算机*（CISC），典型代表包括采用 `x86` 架构的处理器；二是通过精简指令集、简化指令功能，以提升指令执行效率，称为*精简指令系统计算机*（RISC），典型代表包括 `ARM`、`MIPS` 等架构的处理器。

### 4.4.1 $CISC$的主要特点

- 指令系统庞大复杂。
- 指令长度不固定，指令格式和寻址方式种类繁多。
- 多数指令均可直接访问内存。
- 各类指令使用频率差异显著。
- 指令执行时间相差较大。
- 控制器多采用微程序控制。
- 难以通过优化编译生成高效的目标代码。

### 4.4.2 $RISC$的主要特点

- 仅选取使用频率最高的简单指令，复杂指令功能由多条简单指令组合实现。
- 指令长度固定，指令格式和寻址方式种类很少。
- 仅 `LOAD/STORE` 指令可访问内存，其余运算均在寄存器之间进行。
- `CPU` 中配备大量通用寄存器。
- 普遍采用指令流水线技术，绝大多数指令在一个时钟周期内完成。
- 以硬布线控制为主。
- 高度依赖编译器优化。

### 4.4.3 $CISC$和$RISC$的比较

两者主要区别如下：

| 对比项目 | CISC | RISC |
| --- | --- | --- |
| 指令系统 | 复杂、庞大 | 简单、精简 |
| 指令数目 | 一般大于 $200$ 条 | 一般小于 $100$ 条 |
| 指令字长 | 不固定 | 定长 |
| 可访存指令 | 不加限制 | 只有 `LOAD/STORE` 指令 |
| 各种指令执行时间 | 相差较大 | 绝大多数在一个周期内完成 |
| 各种指令使用频度 | 相差很大 | 都比较常用 |
| 通用寄存器数量 | 较少 | 多 |
| 目标代码 | 难以用优化编译生成高效的目标代码程序 | 依赖编译器优化 |
| 控制方式 | 绝大多数为微程序控制 | 绝大多数为组合逻辑控制 |
| 指令流水线 | 可以通过一定方式实现 | 必须实现 |

# 相关题目

指令系统的题主要集中在指令字长、操作码扩展、寻址方式、汇编指令语义和机器级代码分析上。下面把本章题目统一放在最后。

**$1$、一个处理器中共有 $32$ 个寄存器，使用 $16$ 位立即数，其指令系统结构中共有 $142$ 条指令。在某给定程序中，$20\%$ 的指令带有一个输入寄存器和一个输出寄存器；$30\%$ 的指令带有两个输入寄存器和一个输出寄存器；$25\%$ 的指令带有一个输入寄存器、一个输出寄存器、一个立即数；其余 $25\%$ 的指令带有一个立即数输入和一个输出寄存器。**

（1）对于以上四种指令类型的任意一种来说，共需要多少位？假定指令系统结构要求所有指令长度必须是 $8$ 的整数倍。

（2）与使用定长指令集编码相比，当使用变长指令集编码时，该程序能够占用多少存储器空间？

**答案：**

（1）$32$ 个寄存器需要 $5$ 位编号；$142$ 条指令需要 $\lceil\log_2 142\rceil=8$ 位操作码；立即数为 $16$ 位。各类指令的字段位数为：

- 类型一：$8+5+5=18$ 位，向上取整到 $24$ 位（$3$ 字节）。
- 类型二：$8+5+5+5=23$ 位，向上取整到 $24$ 位（$3$ 字节）。
- 类型三：$8+5+5+16=34$ 位，向上取整到 $40$ 位（$5$ 字节）。
- 类型四：$8+16+5=29$ 位，向上取整到 $32$ 位（$4$ 字节）。

（2）变长编码下，平均每条指令长度为：

$$
0.2\times24+0.3\times24+0.25\times40+0.25\times32=30\ \text{位}=3.75\ \text{B}.
$$

若程序有 $I$ 条指令，则变长编码占用 $3.75I$ 字节。定长编码必须按最长指令取 $40$ 位，即每条 $5$ 字节，共 $5I$ 字节。变长编码节省：

$$
5I-3.75I=1.25I\ \text{B},
$$

即节省 $25\%$。

> 这题是变长指令编码的模板题：先算各类指令的字段位数，再按字节向上取整，最后按比例求平均。

**$2$、假设指令字长是 $16$ 位，操作数的地址码是 $6$ 位，指令有零地址、一地址、二地址 $3$ 种格式。**

（1）设操作码固定，若零地址指令有 $M$ 种，一地址指令有 $N$ 种，则二地址指令最多有多少种？

（2）采用扩展操作码技术，二地址指令最多有几种？

（3）采用扩展操作码技术，若二地址指令有 $P$ 条，零地址指令有 $Q$ 条，则一地址指令最多有几种？

**答案：**

（1）二地址指令的地址码占 $12$ 位，操作码只剩 $4$ 位，所以定长操作码共有 $2^4=16$ 种。零地址和一地址指令也共用这 $16$ 个操作码，因此二地址指令最多：

$$
16-M-N
$$

种（要求 $M+N\le16$）。

（2）采用扩展操作码时，若把所有 $4$ 位操作码都留给二地址指令，则最多 $16$ 种。

（3）二地址指令用掉 $P$ 个 $4$ 位操作码后，还剩 $16-P$ 个前缀可用于一地址指令。每个前缀后面接 $6$ 位地址字段，可形成 $2^6=64$ 个一地址操作码，所以一地址操作码总数为：

$$
(16-P)\times64.
$$

其中要为 $Q$ 条零地址指令预留扩展前缀。每条一地址操作码再扩展 $6$ 位可形成 $64$ 个零地址操作码，因此需要预留：

$$
\left\lceil\frac{Q}{64}\right\rceil
$$

个一地址操作码。于是一地址指令最多：

$$
(16-P)\times64-\left\lceil\frac{Q}{64}\right\rceil
$$

种。若 $Q$ 恰好是 $64$ 的倍数，最后一项就是 $Q/64$。

**$3$、在一个 $36$ 位长的指令系统中，设计一个扩展操作码，使之能表示下列指令：**

（1）$7$ 条具有两个 $15$ 位地址和一个 $3$ 位地址的指令。

（2）$500$ 条具有一个 $15$ 位地址和一个 $3$ 位地址的指令。

（3）$50$ 条无地址指令。

**答案：**

一种可行设计如下。

（1）格式一有两个 $15$ 位地址和一个 $3$ 位地址，共占 $15+15+3=33$ 位，剩下 $36-33=3$ 位作为操作码。$3$ 位操作码有 $8$ 个编码，用 `000`～`110` 表示 $7$ 条指令，保留 `111` 作为扩展前缀。

（2）格式二有一个 $15$ 位地址和一个 $3$ 位地址，共占 $18$ 位，剩下 $18$ 位作为操作码。它的前 $3$ 位固定为 `111`，后 $15$ 位作为扩展操作码。$15$ 位扩展码共有 $2^{15}$ 个，取编号 $0$～$499$ 的 $500$ 个编码表示这 $500$ 条指令，保留全 $1$ 编码 `111111111111111` 作为零地址指令的扩展前缀。

（3）格式三无地址，操作码共 $36$ 位。它以前面的 `111 111111111111111` 作为前缀，后面再接 $18$ 位扩展码。$18$ 位扩展码取编号 $0$～$49$ 的 $50$ 个编码，即可表示 $50$ 条无地址指令。

> 扩展操作码的方案不唯一，只要不出现短操作码是长操作码前缀、各操作码不重复即可。

**$4$、按字节编址的计算机中，某 `double` 型数组 $A$ 的首地址是 `2000H`，使用变址寻址和循环结构访问数组 $A$。保存数组下标的变址寄存器初值为 $0$，每次循环取一个数组元素，其偏移地址为变址值乘以 `sizeof(double)`，取完以后变址寄存器的内容自动加 $1$。若某次循环所取元素的地址是 `2100H`，则进入该次循环时变址寄存器的内容是（ ）。**

$A$．$25$

$B$．$32$

$C$．$64$

$D$．$100$

**答案：**$B$。

变址寻址的有效地址为 $EA=(IX)+A$。数组首地址 $A=\text{2000H}$，目标地址 $EA=\text{2100H}$，所以：

$$
(IX)=\text{2100H}-\text{2000H}=\text{100H}=256.
$$

`double` 占 $64$ 位，即 $8$ 字节，因此变址寄存器中保存的数组下标为：

$$
\frac{256}{8}=32.
$$

所以选 $B$。

**$5$、假设 $R[ax]=\text{FFE8H}$，$R[bx]=\text{7FE6H}$，执行指令 `add ax, bx` 后，寄存器的内容和各标志的变化为（ ）。**

$A$．$R[ax]=\text{7FCEH}$，$OF=1$，$SF=0$，$CF=0$，$ZF=0$

$B$．$R[bx]=\text{7FCEH}$，$OF=1$，$SF=0$，$CF=0$，$ZF=0$

$C$．$R[ax]=\text{7FCEH}$，$OF=0$，$SF=0$，$CF=1$，$ZF=0$

$D$．$R[bx]=\text{7FCEH}$，$OF=0$，$SF=0$，$CF=1$，$ZF=0$

**答案：**$C$。

$\text{FFE8H}+\text{7FE6H}=\text{17FCEH}$，低 $16$ 位为 $\text{7FCEH}$，所以 `ax` 的内容为 $\text{7FCEH}$。无符号加法产生进位，因此 $CF=1$。按有符号数看，$\text{FFE8H}=-24$，$\text{7FE6H}=32742$，两者之和为 $32718$，仍在 $16$ 位有符号数范围内，所以 $OF=0$。结果为正，$SF=0$；结果不为零，$ZF=0$。因此选 $C$。

> 这题容易把 $CF$ 和 $OF$ 弄反：无符号进位看 $CF$，有符号溢出看 $OF$。

**$6$、假设 $R[ax]=\text{7FE6H}$，$R[bx]=\text{FFE8H}$，执行指令 `sub bx, ax` 后，寄存器的内容和各标志的变化为（ ）。**

$A$．$R[ax]=\text{8002H}$，$OF=0$，$SF=1$，$CF=1$，$ZF=0$

$B$．$R[bx]=\text{8002H}$，$OF=0$，$SF=1$，$CF=0$，$ZF=0$

$C$．$R[ax]=\text{8002H}$，$OF=1$，$SF=1$，$CF=0$，$ZF=0$

$D$．$R[bx]=\text{8002H}$，$OF=1$，$SF=1$，$CF=0$，$ZF=0$

**答案：**$B$。

$\text{FFE8H}-\text{7FE6H}=\text{8002H}$，结果存入 `bx`，所以 `ax` 不变。无符号减法没有借位，因此 $CF=0$。按有符号数看，$\text{FFE8H}=-24$，$\text{7FE6H}=32742$，$-24-32742=-32766$，仍在 $16$ 位有符号数范围内，所以 $OF=0$。结果为负，$SF=1$；结果不为零，$ZF=0$。因此选 $B$。

**$7$、某计算机的数据采用小端方式存储，减法指令 `sub ax, imm` 的功能为 $(ax)-imm\rightarrow ax$，`imm` 表示立即数。该指令对应的十六进制机器码为 `2Dxxxx`（从左到右以字节为单位由低地址到高地址），其中 `xxxx` 对应 `imm` 的机器码。若 `imm = -3`，$(ax)=7$，则该指令对应的机器码和执行后 `OF` 标志位的值分别为（ ）。**

$A$．`2DFFFDH`，$0$

$B$．`2DFFFDH`，$1$

$C$．`2DFDFFH`，$0$

$D$．`2DFDFFH`，$1$

**答案：**$C$。

`imm = -3` 的 $16$ 位补码为 $\text{FFFDH}$。小端方式下低字节 `FD` 存放在低地址，高字节 `FF` 存放在高地址，所以机器码的字节顺序为 `2D FD FF`，即 `2DFDFFH`。执行 $7-(-3)=10$，结果在 $16$ 位有符号数范围内，因此 $OF=0$。所以选 $C$。

> 手写答案 $A$ 对应的是把立即数按大端顺序写成 `FF FD`；题目明确说小端，所以应选 $C$。

**$8$、某C语言程序中对数组变量 `b` 的声明为 `int b[10][5];`，有一条 `for` 语句如下：**

```c
for (i = 0; i < 10; i++)
{
    for (j = 0; j < 5; j++)
    {
        sum += b[i][j];
    }
}
```

假设执行到 `sum += b[i][j];` 时，`sum` 的值在 `EAX` 中，`b[i][0]` 所在的地址在 `EDX` 中，`j` 在 `ESI` 中，则 `sum += b[i][j];` 所对应的指令（AT&T格式）可以是（ ）。

$A$．`addl 0(%edx, %esi, 4), %eax`

$B$．`addl 0(%esi, %edx, 4), %eax`

$C$．`addl 0(%edx, %esi, 2), %eax`

$D$．`addl 0(%esi, %edx, 2), %eax`

**答案：**$A$。

`b[i][j]` 的地址等于 `b[i][0]` 的地址加上 $j\times\text{sizeof(int)}$。`int` 占 $4$ 字节，所以比例因子为 $4$。`b[i][0]` 的地址在 `EDX`，`j` 在 `ESI`，AT&T格式的源操作数在前、目的操作数在后，因此对应指令为 `addl 0(%edx, %esi, 4), %eax`。

**$9$、假设P为调用过程，Q为被调用过程，程序在IA-32处理器上执行。以下是C语言程序中过程调用所涉及的操作：**

- ① 过程Q保存P的现场，并为非静态局部变量分配空间
- ② 过程P将实参存放到Q能访问到的地方
- ③ 过程P将返回地址存放到特定处，并跳转到Q执行
- ④ 过程Q取出返回地址，并跳转回过程P执行
- ⑤ 过程Q恢复P的现场，并释放局部变量所占空间
- ⑥ 执行过程Q的函数体

过程调用的正确执行步骤是（ ）。

$A$．②→③→④→①→⑤→⑥

$B$．②→③→①→④→⑥→⑤

$C$．②→③→①→⑥→⑤→④

$D$．②→③→①→⑤→⑥→④

**答案：**$C$。

先由P传实参（②），再由 `call` 保存返回地址并转到Q（③）；Q建立栈帧、保存现场并分配局部变量（①），然后执行函数体（⑥）；函数体执行完后恢复现场、释放局部变量（⑤），最后由 `ret` 取出返回地址并返回P（④）。因此顺序为 ②→③→①→⑥→⑤→④。

**$10$、【$2017$ 统考真题】在按字节编址的计算机M上，`f1` 的部分源程序如下。将 `f1` 中的 `int` 都改成 `float`，可得到计算 $f(n)$ 的另一个函数 `f2`。**

    ...         ...         ...

（1）计算机M是RISC还是CISC？为什么？

（2）`f1` 的机器指令代码共占多少字节？要求给出计算过程。

（3）第 $20$ 条指令 `cmp` 通过 $i-(n-1)$ 实现对 $i$ 和 $n-1$ 的比较。执行 `f1(0)` 的过程中，当 $i=0$ 时，`cmp` 指令执行后，进位/借位标志 `CF` 的内容是什么？要求给出计算过程。

（4）第 $23$ 条指令 `shl` 通过左移操作实现了 `power * 2` 运算。在 `f2` 中能否用 `shl` 指令实现 `power * 2`？为什么？

**答案：**

（1）M是CISC。理由：指令长度可变（例如 `push ebp` 为 $1$ 字节，`cmp` 为 $3$ 字节，`shl` 为 $2$ 字节），且支持内存操作数和较复杂的指令，符合CISC的特征；RISC通常采用定长指令和load/store结构。

（2）最后一条指令 `ret` 位于 `0040107FH`，长度为 $1$ 字节，所以代码结束地址为 `00401080H`。代码总长度为：

$$
\text{00401080H}-\text{00401020H}=\text{60H}=96\ \text{B}.
$$

（3）$n=0$ 时，$n-1$ 按无符号数下溢为 `FFFFFFFFH`。`cmp` 计算 $i-(n-1)$：

$$
0-\text{FFFFFFFFH}=\text{00000001H}.
$$

这个减法需要向高位借位，因此 `CF=1`。也正因为 $n-1$ 变成了最大的无符号数，循环条件 $i\le n-1$ 恒成立，`f1(0)` 实际上会陷入死循环。

（4）不能。`shl` 是整数逻辑左移指令，只能对整数位串做移位；`float` 采用符号位、阶码、尾数的编码，直接左移整个位串并不等于把浮点数值乘以 $2$。`f2` 中应使用浮点乘法或加法指令，例如 `mulss`，或者用 `addss` 让 `power` 与自身相加。

**答案：**

（1）$f(10)$ 先调用 `f1(10)`，再递归调用 `f1(9)`、`f1(8)`、……、`f1(1)`，共 $10$ 次。递归调用由第 $16$ 行的 `call f1` 指令完成。

（2）第 $12$ 行的 `jle f1+35h` 是条件转移指令。第 $16$ 行的 `call`、第 $20$ 行的 `jmp` 和第 $30$ 行的 `ret` 一定会使程序转移执行。

（3）第 $16$ 行的 `call` 指令长 $5$ 字节，起始地址为 `00401025H`，所以第 $17$ 行指令的地址为：

$$
\text{00401025H}+5=\text{0040102AH}.
$$

`call` 的目标地址为 `00401000H`，因此偏移量为：

$$
\text{00401000H}-\text{0040102AH}=-\text{2AH}=-42,
$$

即 `FFFFFFD6H`。指令中偏移量的字节为 `D6 FF FF FF`，低字节 `D6` 存放在低地址，所以M采用小端方式。

（4）$13!=6227020800$，超过了 $32$ 位有符号整数 `int` 的最大值 $2^{31}-1=2147483647$，发生溢出。按 $32$ 位取模：

$$
6227020800-2^{32}=1932053504,
$$

所以 `f1(13)` 返回 $1932053504$。要使结果正确，应把返回值类型改为 $64$ 位整数，例如 `long long`，并保证乘法在 $64$ 位下进行：

```c
long long f1(int n)
{
    if (n > 1)
    {
        return (long long)n * f1(n - 1);
    }
    else
    {
        return 1;
    }
}
```

（5）`imul eax, ecx` 的完整乘积是 $64$ 位，但指令只把低 $32$ 位写回 `eax`，高 $32$ 位用于设置溢出标志，不写入 `edx`。更准确地说，当乘积的高 $33$ 位（第 $63$ 位到第 $31$ 位）不全为 $0$ 且不全为 $1$ 时，说明乘积无法用 $32$ 位有符号数表示，此时 `OF=1`。等价地，高 $32$ 位不是低 $32$ 位符号位的扩展时，`OF=1`。编译器可以在 `imul` 后加一条溢出自陷指令，例如 `into`，使 $CPU$ 在 `OF=1` 时转入溢出异常处理程序；也可以用 `jo` 跳转到异常处理程序。
